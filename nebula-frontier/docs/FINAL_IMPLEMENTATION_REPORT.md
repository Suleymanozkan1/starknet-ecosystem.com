## 1. Executive Summary

NEBULA FRONTIER is an original, persistent 3D space MMO for browser, Android and iOS. It uses a Solana **devnet** reward economy.
- **Codebase:** a pnpm monorepo of 22 workspaces, about 51k lines of TypeScript in 382 source files.
- **Platforms:** the Android debug APK builds (locally and in CI), the iOS app builds on macOS CI (simulator app + unsigned .ipa), and a static no-backend demo runs on Vercel. The Docker Compose stack runs end to end.
- **Server:** Colyseus is authoritative: rooms with AOI, anti-cheat, persistence, bots, raids, PvP, clan wars, events, pets and reputation.
- **API:** Fastify with 113 routes: auth, SIWS wallet login, CSRF, RBAC admin, market and auction, clans, social, economy, wallet.
- **Database:** Postgres, a Prisma 7 schema with 86 models, and a double-entry, append-only ledger.
- **Economy:** budgets, caps, treasury health, circuit breakers, and an inflation and anomaly controller.
- **Blockchain service:** the only holder of the treasury key. It runs a durable withdrawal queue and verifies payouts.
- **Clients:** a React/Vite web app (27 pages, complete TR/EN, mobile layout, ARIA tutorial guide), a Three.js world with a Phaser radar/HUD layer, an admin console, and a Capacitor mobile shell.

The §144 MVP vertical slice runs end to end in `tests/integration/vertical-slice.test.ts`: account, faction, ship, enter the world, move, kill an NPC, level up, loot, inventory and equip, PvP, event reward, crypto claim, and withdrawal to a transaction signature. The only step not proven on the real chain is the devnet payout. The devnet faucet returns 429 to this environment, so the treasury has 0 SOL; the payout is proven against a mock chain that decodes the real signed transactions.

**Completion: 251 / 257 = 97.7%** (Implemented / Total). 6 are partial — all of them need a real devnet transaction (unfunded treasury) — 0 are not implemented, and 0 are blocked.

## 7. API Audit

Fastify, with 113 route handlers. Every body, query and parameter is validated with zod (`packages/validation`).

**Auth:**
- Cookie sessions: httpOnly, Secure, SameSite.
- Rotating refresh tokens and a CSRF double-submit header.
- SIWS wallet login: nonce, signature, verification. The nonce is single-use and expires.

**Access control:** RBAC for admin routes, and every admin action is audit-logged.

**Rate limits:** on auth, wallet, withdrawal, chat, purchase and market.

**Operations:** `/health`, `/ready` (checks DB and Redis) and `/metrics` (Prometheus), all tested in `platform-config.test.ts`.

**Integration tests:** `auth`, `api`, `market`, `wallet`, `platform`, `premium`, `clan-station`, `account-security`, `social-gameplay`, `rotation`.

## 8. Database Audit

**Schema:**
- Postgres 16, Prisma 7.10 (`prisma-client` generator, `@prisma/adapter-pg`).
- 86 models, 8 non-destructive migrations. The newest two are the deposit gem-grant lock and the clan-mission event receipts.

**Money:**
- All money movements go through `post()`. It requires a transaction and an idempotency key.
- It uses a conditional decrement, so user balances never go negative.
- Idempotency races resolve as duplicates.
- Corrections are compensating reversals with a fixed key; a COMPENSATION entry cannot be reversed.

**Integrity check:** `verifyLedgerIntegrity` compares every account balance with a replay of its journal, which detects drift.

**Isolation:** SERIALIZABLE transactions, with retries, for config changes, circuit breakers, risk updates and bootstrap.

**Idempotency:** unique `originRef` / `idempotencyKey` values on persistence. The clan-mission event receipts make retried events no-ops.

**Backups:**
- A daily `pg_dump` with checksum and 30-day retention.
- A restore drill was verified.
- WAL archiving is configured for point-in-time recovery; see §22 for the one caveat.

## 9. Multiplayer Audit

**Rooms:** Colyseus 0.18 with 11 room types. The server is authoritative; clients send only intents, validated with zod and sanitized. Chat strips invisible Unicode.

**Anti-cheat:**
- server-enforced speed, fire rate and cooldowns;
- packet-rate limits;
- AOI replication through StateView;
- anomaly risk signals.

**Tickets:** HS256, 60-second lifetime, single use through Redis `SET NX`, with key rotation. Tickets are bound to their map for sector, boss, event, gate, raid and PvP rooms.

**Persistence:**
- Batched and idempotent.
- A failed final flush goes into a retry queue, drained on dispose and shutdown.
- A committed delta is never re-applied.

**Tested:**
- reconnection within the window, consented leave, window expiry and room shutdown (`reconnection.test.ts`);
- concurrent ticket redemption, both in memory and in Redis.

**Limits:** Redis presence and driver are wired for horizontal scaling, but a two-node matchmaking run has not been tested. A 100-client (50v50-scale) load test is recorded in §23: tick p95 ≤ 35 ms at 20 Hz.

## 12. Blockchain Audit

**Network:** Solana **devnet** only, enforced by an RPC genesis/cluster check. It uses `@solana/kit`, and the wallet adapter supports Phantom, Solflare, and Wallet Standard wallets such as Backpack.

**Deposits:** each deposit is bound to a server memo, and verification checks:
- network, mint, amount and recipient;
- memo and sender;
- confirmation, and that the signature has not been used before.

One bad signature no longer strands a paid deposit.

**Withdrawals:**
- limits, cooldown and review;
- a durable queue in Postgres plus BullMQ;
- the signature is saved before confirmation, and a withdrawal is never marked COMPLETED without confirmation;
- retries with backoff;
- a memo-matched transaction is **verified** before it is adopted as the payout: the treasury must be fee payer and signer, and the transfer must be exact.

**Keys:**
- The treasury key loads only when `SERVICE_ROLE=blockchain`, from `TREASURY_SECRET_FILE` (0600). It is never in the shared `.env`, the frontend, logs or git.
- The mock RPC is only exported through `@nebula/blockchain/testing`.

**Runtime:** the payout and deposit pipelines pass end to end against a mock chain that decodes the real signed transactions. **Real devnet transactions are BLOCKED:** the faucet returns 429, and treasury `Hd6r6rGc8CNXRzYV8DwsU6vqh8aPM3711r2UC8Z3vbhe` holds 0 SOL.

**Anchor program:**
- `initialize` is restricted to the upgrade authority.
- It has `update_config`, a two-step authority transfer, a per-epoch emission cap, and pause checks.
- `cargo test` runs 6 unit tests, all passing.
- It is not deployed, by design, for the MVP.

## 13. Economy Audit

**Reward budget:**
- The budget is season revenue × `rewardBudgetRatio`, with caps.
- Treasury-health multipliers apply (HEALTHY, WATCH, WARNING, CRITICAL).
- A hard emission cap applies, and the daily cap is scoped per season.
- Per-player daily, weekly and season caps.

**Controls:**
- Eligibility checks and risk review.
- Circuit breakers (REWARD_PAUSE, MARKET_PAUSE, WITHDRAWAL_REVIEW, EVENT_PAUSE), toggled atomically together with their audit record.
- An inflation and anomaly controller, whose DAU baseline comes from snapshot history.
- Reward review and claim transitions are conditional.

**Deposits:** the gem grant is locked when the deposit is prepared.

**Treasury bootstrap:** reconciles against the real on-chain balance, and in SPL-mint mode SOL can never back NEBX.

**No unlimited mint:** supply is fixed.

The economy simulation (§24) found 0 invariant violations.

## 15. Anti-Cheat Audit

**Server-side authority:** only the server simulates. It enforces speed (movement validation), fire rate (the `FireRateAuditor` window check), cooldowns, packet rate, and range and line checks for targeting and pickup.

**Anti-farming:**
- repeat PvP kills of the same victim inside a window pay nothing;
- leavers gain no rating;
- raids have a daily entry limit (atomic across instances), a minimum pilot count, and scaling of XP, credits and loot by participation.

**Integrity:** loot is granted once (the `originRef` is unique), and escrowed stacks are protected. Anomalies become risk signals that feed reward and withdrawal review.

**Tests:** `packages/game-core/src/anticheat.test.ts`, `review-fixes.test.ts`, `game-server.test.ts`.
